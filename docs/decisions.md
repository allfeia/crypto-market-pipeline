# Архитектурные решения

## ADR-001. Разделение collectors по биржам

Bybit и OKX запускаются отдельными процессами. Сбой одного WebSocket не должен останавливать сбор с другой биржи.

## ADR-002. Общие Kafka topics по типу события

Trades публикуются в `market.trades`, orderbook — в `market.orderbook`. Биржа и символ передаются в полях события и Kafka key.

## ADR-003. Raw-слой в MinIO

Исходные нормализованные события сохраняются в объектном хранилище. Это позволяет повторно запускать преобразования без повторного запроса к биржам.

## ADR-004. Trino как SQL-движок

Trino читает Parquet через Iceberg Catalog и предоставляет SQL-доступ для dbt. Spark в локальный проект не добавляется, поскольку потоковые и batch-задачи не требуют его масштаба.

## ADR-005. ClickHouse для аналитических витрин

ClickHouse получает очищенные и агрегированные модели. Raw-архив остаётся в MinIO.

## ADR-006. Гарантия доставки

На текущем этапе целевая гарантия — at-least-once. Поэтому обработка должна быть идемпотентной, а дедупликация должна выполняться по `event_id`.

## ADR-007. Граница текущего этапа

Текущий этап заканчивается на доставке Kafka-событий в raw Parquet. Iceberg, Trino, dbt, ClickHouse, Airflow и Telegram добавляются отдельными этапами и не считаются готовыми заранее.

## ADR-008. Идемпотентная запись Parquet

Имя Parquet-part строится из hash канонических строк batch-а. Повторная запись того же batch после сбоя перезаписывает тот же object key, а не создаёт новый файл.

Дедупликация текущего archiver действует в пределах буфера до успешного flush. Долговременная дедупликация после рестарта относится к будущему table layer.

## ADR-009. Стабильная идентификация orderbook

UUID orderbook строится из идентификатора обновления биржи. Один и тот же update после reconnect сохраняет тот же `event_id`, что позволяет обнаруживать повторную доставку. Если биржа сбрасывает собственный sequence ID и повторно использует его для другого сообщения, для полной защиты потребуется отдельная проверка последовательности стакана.

## ADR-010. Backpressure при ошибке sink

Ошибки нормализации считаются постоянными для конкретного сообщения и приводят к его пропуску с записью в лог. Ошибка sink считается временной. Collector удерживает это сообщение и повторяет запись с exponential backoff до восстановления sink, чтобы не терять Kafka-события.

## ADR-011. Почасовое raw partitioning

Raw Parquet partition path содержит только `date` и `hour` в UTC. `exchange`, `event_type` и `symbol` хранятся колонками внутри файлов. Это уменьшает small-files problem при разной интенсивности Bybit и OKX.

Это правило реализовано в текущем `HourlyArchive`.
